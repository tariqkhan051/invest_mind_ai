# 1. Purpose

This document defines the business domain of the AI Investment Manager.

It is independent of:

- Programming Language
- Database
- Framework
- APIs
- AI Providers
- UI
- Infrastructure

This document defines **what the business is**, not **how it is implemented**.

Every Python class, database table, API endpoint, repository, service, and AI agent should ultimately trace back to the concepts defined here.

---

# 2. Domain Philosophy

The AI Investment Manager is fundamentally an **intelligent decision-support system**, not a trading platform.

Its responsibilities are to:

- Collect information
- Understand market conditions
- Evaluate the user's portfolio
- Estimate future opportunities
- Optimize allocations
- Explain recommendations
- Learn from outcomes

The user remains the final decision maker.

---

# 3. Ubiquitous Language

All contributors should use the same terminology.

The following words have precise meanings.

| Term | Definition |
|-------|------------|
| Portfolio | Complete collection of user investments |
| Holding | Current ownership in a fund or stock |
| Transaction | Any buy, sell, switch, dividend or adjustment |
| Fund | Mutual Fund or Cash Management Fund |
| Stock | Individual PSX-listed company |
| Recommendation | Suggested investment action |
| Prediction | Forecast generated by quantitative models |
| Strategy | Rules used to generate recommendations |
| Snapshot | Portfolio state at a specific point in time |
| Market Data | External financial information |
| Macro Indicator | Economic metric such as CPI or Policy Rate |
| Signal | Computed indicator used during analysis |
| Feature | Machine-learning input variable |
| Model | Mathematical or ML algorithm |
| Confidence | Estimated reliability of a recommendation |
| Risk Score | Overall investment risk measurement |
| Learning Record | Historical evaluation of previous recommendations |
| Backtest | Historical simulation of a strategy |

These terms should be used consistently throughout the project.

# 12. Domain Invariants

Business rules that must always remain true.

Examples:

A Portfolio must have exactly one owner.

Holdings cannot have negative quantities.

NAV cannot be negative.

Recommendation confidence must remain between 0 and 100.

Allocation percentages must total approximately 100%.

Historical transactions must never be deleted.

Predictions cannot exist without input data.

Learning records cannot exist without recommendations.

Violating an invariant should raise a domain exception.

# 16. Business Rules

# 23. Portfolio Rules

The Portfolio must always satisfy these invariants.

- Exactly one owner.
- One base currency.
- Holdings cannot contain duplicates for the same asset.
- Total allocation must be computable.
- Historical transactions are immutable.
- Snapshot history cannot be modified.
- Every change increments the portfolio version.
- Portfolio value must never be negative.
- Monthly SIP cannot be negative.
- Portfolio cannot contain unsupported asset types.

# 34. Validation Rules

A valid Portfolio must satisfy:

- At least one owner.
- Base currency defined.
- Risk profile defined.
- Investment preference defined.
- No duplicate active holdings for the same asset.
- No orphan transactions.
- Every transaction belongs to one holding.
- Every holding belongs to one portfolio.
- Portfolio value is internally consistent.
- Allocation calculations reconcile with holding values.

Validation failures should raise domain-specific exceptions and prevent state changes.
